# ユビキタス言語

この催事予約アプリの会話・画面・モデル・テストで使う業務用語をまとめます。
実装や業務ルールの整理で意味が変わった場合は、対応するコード名とあわせて更新します。
メソッド名は現時点の候補であり、実装時に調整します。

## 業務上の概念

| 用語 | 意味 | コード上の表現 |
| --- | --- | --- |
| 催事 | 利用者が参加を予約する催し。1つの開催期間・会場・定員を持つ | `Event` |
| 会場 | 催事を開催する場所。1つの催事には1つの会場があり、同じ会場で複数の催事を開催できる | `Venue` |
| 開催期間 | 催事の開始時刻から終了時刻までの期間。開始時刻は終了時刻より前である | `EventPeriod` |
| 利用者（客） | 催事を閲覧し、予約・キャンセルを行う人。ユースケース図のアクター | `userId` で識別 |
| 管理者 | 催事の作成を行える人 | `ADMIN` ロール |
| 予約者 | ある予約を行った利用者。その予約をキャンセルできる本人 | `Reservation.userId` |
| 予約 | 利用者が特定の催事に参加するために確保した1席。予約者と状態、予約日時を持つ | `Reservation` |
| 催事の空き状況 | 催事と有効な予約数から、その時点の残席・満席・予約受付可否を表す | `EventAvailability` |
| 定員 | 催事ごとに受け付けられる人数の上限。正の整数 | `Event.capacity` |
| 有効な予約 | 状態が「予約済み」であり、キャンセルされていない予約 | `status === "reserved"` |
| 予約数 | ある催事の有効な予約の件数。1予約は1席なので、確保済みの席数でもある | `EventAvailability.reservationCount` |
| 残席 | 定員から予約数を引いた、まだ予約できる席数 | `EventAvailability.remainingSeats()` |
| 満席 | 予約数が定員に達し、空席がない状態 | `EventAvailability.isFull()` |
| 開始済み | 現在時刻が催事の開始時刻以降であること。開始時刻ちょうどを含む | `Event.hasStarted(now)` |

日本語では「催事」を基本とし、「イベント」も同じ概念を指します。コードでは `Event` に統一します。
「予約数」は、特に断りがなければ有効な予約数を指します。キャンセル済みの記録を含む総件数とは区別します。

## 操作と状態

| 用語 | 意味 | コード上の表現 |
| --- | --- | --- |
| 催事を作成する | 管理者が催事名・会場・開催期間・定員を指定して新しい催事を登録する | `EventApplicationService.create` |
| 予約する | 開始前で空席があり、本人の有効な予約がない催事に、新しい予約を成立させる | `ReservationApplicationService.reserve` |
| 予約済み | 予約が成立し、1席を確保している状態 | `ReservationStatus` の `reserved` |
| キャンセルする | 予約者本人が、催事の開始前に有効な予約を取り消し、確保していた席を解放する | `ReservationApplicationService.cancel` |
| キャンセル済み | 席の確保を解除した状態。予約の記録は残り、予約数には含めない | `ReservationStatus` の `cancelled` |
| 再予約する | キャンセル後に、予約条件を満たす同じ催事へ新しいIDの予約を成立させる | 通常の `reserve`。別ユースケースは設けない |
| 重複予約 | 同じ利用者が同じ催事に複数の有効な予約を持つこと。初期モデルでは禁止する | 催事ID・利用者ID・`reserved` の条件で存在を確認 |

## 空席と予約可否

「空席がある」は残席があることだけを表します。開始済みの催事でも、席数としての空きがある場合があります。

`EventAvailability.isReservable(now)` は、空き状況として開始前かつ空席があるかを判断します。
利用者の予約を実際に成立させるには、さらに本人の有効な予約がないことを確認します。
その判定をDomain Serviceへ切り出すかは実装時に決定します。
